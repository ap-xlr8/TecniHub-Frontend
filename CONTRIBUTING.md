# Contribuir

1. Las ramas HU aprobadas nacen de `sprint/nombre-sprint`, y se integran mediante PR al sprint; luego el sprint llega a `developer`, una release estabilizada a `main`.
2. Usa Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
3. Ejecuta `npm ci`, formato, lint, build, verificación PWA y tests antes de abrir PR.
4. Adjunta resultados realmente ejecutados y revisa que no haya secretos ni artefactos en el cambio.
5. Hay una sola persona desarrolladora actualmente: documenta auto-revisión y CI; no finjas una aprobación independiente.
